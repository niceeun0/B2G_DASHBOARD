# 정부지원사업 대시보드 자동화 + 아웃바운드 메일 관리

## 1. 전체 그림

```
매일 새벽                                            매일 실행 직후
┌─────────────────┐   append_to_accumulator()   ┌──────────────────────┐
│ bizinfo_bot.py   │ ───────────────────────────▶ │ data/                │
│ (기업마당 신규공고│                              │  daily_accumulated   │
│  수집 + 메일발송)│                              │  .xlsx (계속 누적)   │
└─────────────────┘                              └──────────┬───────────┘
                                                              │
                                                   build_dashboard.py
                                                              │
        data/institutions_master.csv (고정, ①) ───┐          ▼
        data/yearly_history.xlsx     (고정, ②) ───┼──▶ outputs/정부지원사업_대시보드.xlsx
                                                    │      (5개 시트, 매번 새로 생성)
                                                    ┘
                                                              │
                                                   outbound_email_manager.py
                                                              │
                                                              ▼
                                                   "아직 안 보낸 담당자만" 목록
```

핵심: **③(매일업로드 데이터)만 계속 자라고, 나머지는 매번 처음부터 다시 계산**합니다.
그래서 대시보드가 "변하는" 이유는 오직 ③ 때문이라는 걸 코드로도 보장합니다.

## 2. 파일 구성

```
data/
  institutions_master.csv     # ① 26년 기준 공공기관 현황 (고정 — 손대지 마세요)
  yearly_history.xlsx         # ② 기업마당 1년치 (고정 — 손대지 마세요)
  daily_accumulated.xlsx      # ③ 매일 누적 (bizinfo_bot.py가 매일 자동으로 갱신)
scripts/
  bizinfo_bot.py              # 기존 봇 + 누적파일 갱신 기능 추가
  build_dashboard.py          # ①②③ 매칭·집계해서 대시보드 재생성
  outbound_email_manager.py   # 발송이력 관리 + 다음 발송대상 뽑기
  .github_workflow_dashboard.yml  # → .github/workflows/에 넣으세요
outputs/
  정부지원사업_대시보드.xlsx    # 매번 재생성되는 최종 산출물
  발송이력.csv                 # (처음엔 없음) 발송 기록이 쌓이는 곳
```

## 3. 저장소에 적용하는 방법

1. 기존 `bizinfo_bot.py`를 이 폴더의 `scripts/bizinfo_bot.py`로 교체
2. `scripts/build_dashboard.py`, `scripts/outbound_email_manager.py` 추가
3. `scripts/.github_workflow_dashboard.yml` → `.github/workflows/dashboard.yml` 로 이름 바꿔서 저장
   (기존 뉴스레터 워크플로우가 있다면 두 개를 합쳐도 되고, 별도로 둬도 됩니다)
4. `data/institutions_master.csv`, `data/yearly_history.xlsx`, `data/daily_accumulated.xlsx`를
   저장소의 `data/` 폴더에 커밋 (최초 1회만 — 이후엔 워크플로우가 알아서 갱신)
5. **GitHub Actions 권한 설정 필요**: 저장소 Settings → Actions → General →
   "Workflow permissions"을 **"Read and write permissions"**으로 바꿔야
   워크플로우가 `git push`로 결과를 커밋할 수 있습니다.

## 4. 매칭 로직 (왜 100% 매칭이 안 되는지)

②/③의 "수행기관명"을 ①의 "지점명"과 비교합니다. 지점명이 기관명보다 훨씬
유니크해서(5,972/5,974) 매칭 키로 적합합니다.

**"재단법인 OOO", "사단법인 OOO"처럼 법인격 접두어 차이**를 제거하고 비교하도록
했더니 매칭률이 크게 올랐습니다 (③ 기준 60% → 75%).

그래도 남는 미매칭 기관명들은 대부분:
- **실제로 공공기관이 아닌 민간단체** (대한상공회의소, 한국산업기술진흥협회 등) — ①이
  다루는 범위 자체가 아니라서 정상입니다.
- **기관명이 아닌 텍스트** ("직접수행", "기초자치단체" 등)

`scripts/build_dashboard.py` 실행 로그에 매칭 안 된 기관명 개수가 매번 찍히니,
혹시 진짜 공공기관인데 빠진 게 있으면 로그를 보고 `ENTITY_PREFIXES` 목록에
접두어를 추가하거나 `institutions_master.csv`를 직접 보정하시면 됩니다.

## 5. 점수 계산 공식 (투명하게 새로 정의함)

### 5-1. 지원금액 / 지원갯수 컬럼 (매일업로드_원천데이터에 신규 추가)

"지원 규모는 기업당 최대 45백만원 이내, 28건 내외입니다." 같은 문장을
아래 두 컬럼으로 자동 분리합니다:

| 지원규모 (원문 요약) | 지원금액 | 지원갯수 |
|---|---|---|
| 지원 규모는 기업당 최대 45백만원 이내, 28건 내외입니다. | 4500만원 | 28건 |

- **지원금액**: 문장에서 찾은 금액 중 가장 큰 값을 "OOOO만원" 형태로 표시
- **지원갯수**: 선정 인원/건수를 "OO건" 형태로 통일해서 표시 (원문이 "개사"든
  "명"이든 전부 "건"으로 맞춤 — 다른 단위를 그대로 보고 싶으시면 말씀해주세요)
- 둘 다 이미 요약된 "지원규모" 문장이 아니라, **원문에서 지원규모 관련 구절을
  직접 추출한 텍스트**에서 파싱합니다. 요약을 거치면 "28건 내외**입니다**"처럼
  특정 어미가 붙은 표현이 누락될 수 있어서, 원문에 더 가까운 텍스트를 쓰는
  게 더 정확합니다.
- 금액/갯수를 못 찾으면 빈 칸으로 둡니다 (억지로 추측하지 않음).

**실제 데이터로 검증하다가 진짜 버그를 하나 발견해서 고쳤습니다**: "1.85억원"
같은 소수점 금액을 기존 정규식이 "85억원"(46배 부풀려진 값)으로 잘못 읽고
있었습니다. 이 버그 때문에 전북테크노파크의 "사업규모점수"가 실제로 8554점
(잘못된 값)으로 계산되어 있었는데, 수정 후 정확한 값인 239점으로 바로잡혔습니다
— 우선순위에 실제 영향을 주는 버그였어서 `bizinfo_bot.py`와
`build_dashboard.py` 둘 다에서 고쳤습니다.

### 5-2. 우선순위 종합점수

원본 대시보드의 점수 공식은 역산해봐도 정확히 재현이 안 되는 부분이 있어서,
**설명 가능한 새 공식**으로 정의했습니다 (요청하신 대로):

- **사업규모점수** = 그 기관이 매일데이터에 등록한 모든 공고의 "지원규모" 텍스트에서
  파싱한 금액(최댓값 기준, 백만원 단위)을 전부 합산
  - 참고: 대출/융자성 사업(정책자금 등)은 금액 자체가 커서 점수가 크게 나올 수
    있습니다. "1개 기업당 지원액"이 아니라 "전체 재원 규모"인 경우가 섞여있어서
    참고용으로만 봐주세요.
- **우선순위 종합점수** = 아래 3개를 각각 0~100 백분위로 바꾼 뒤 가중평균
  (가중치는 `build_dashboard.py` 상단 상수로 명시되어 있어 언제든 조정 가능):
  - 서류적합도(총 필요서류 합계) **40%**
  - 사업규모점수 **35%**
  - 활동성(매일데이터 등록 공고수) **25%**
- 백분위(순위 기반) 방식을 써서, 위에서 말한 대출성 사업처럼 금액이 극단적으로
  큰 이상치가 있어도 다른 기관들의 상대 순위를 왜곡하지 않습니다.
- 담당 이메일이 하나도 없는 기관은 "연락가능여부" 컬럼에 별도 표시됩니다
  (점수는 높은데 연락할 방법이 없는 경우를 바로 알 수 있게).

가중치가 마음에 안 들면 `build_dashboard.py` 상단의 `WEIGHT_DOCS` /
`WEIGHT_BUDGET` / `WEIGHT_ACTIVITY` 세 숫자만 바꾸면 됩니다 (합이 1.0이 되게).

## 6. 아웃바운드 메일 관리 사용법

실제 메일 발송 자체는 자동화하지 않았습니다(요청하신 대로). 대신 "누구에게
보내야 할지"와 "누구는 이미 보냈는지"만 관리합니다.

```bash
# 1) 우선순위 상위 50개 기관 중, 아직 안 보낸 담당자만 뽑기
python scripts/outbound_email_manager.py next --top 50

# -> outputs/발송대상_다음배치.xlsx 생성됨
#    (기관명, 우선순위, 발송대상이메일, 이메일개수, 대표전화 등)

# 2) 이 목록으로 실제 메일(메일머지 등)을 보낸 뒤, 발송완료로 기록
python scripts/outbound_email_manager.py mark-sent \
    --from outputs/발송대상_다음배치.xlsx \
    --campaign "2026-08 1차 제안"

# 3) 현황 확인
python scripts/outbound_email_manager.py status

# 4) 다시 next를 실행하면 방금 보낸 사람들은 자동으로 빠지고 다음 순위부터 나옴
python scripts/outbound_email_manager.py next --top 50
```

**추적 단위는 "기관"이 아니라 "이메일 주소"입니다.** 한 기관에 담당자가
여러 명이면, 그중 이미 보낸 사람만 빼고 새 담당자에게는 계속 보낼 수 있습니다.

`outputs/발송이력.csv`가 모든 기록의 원본입니다. 엑셀로 열어서 직접 봐도 되고,
백업/버전관리하고 싶으면 이 파일도 저장소에 커밋해두시면 됩니다.

## 7. 실제 데이터로 검증한 내용

- 대구테크노파크: 매일데이터 2건(Y서류 3개+2개=5개) → 대시보드 "총 필요서류
  합계" 5와 정확히 일치 확인
- 누적 파일에 같은 원문링크의 공고를 두 번 넣어도 중복되지 않는 것 확인
- 발송이력에 10개 기관(86개 이메일) 기록 후 `next` 재실행 시 정확히 그
  10개 기관이 빠지고 11위부터 나오는 것 확인
